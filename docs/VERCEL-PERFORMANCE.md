# การปรับความเร็วและหน้าจอ — 5 พฤศจิกายน 2026

- `vercel.json` กำหนด region `sin1` ให้ใกล้ Supabase `ap-southeast-1` ที่ใช้อยู่ ต้อง deploy รุ่นนี้ใหม่จึงมีผลบน Vercel หากย้ายฐานข้อมูลไปภูมิภาคอื่นต้องเปลี่ยนตาม
- Prisma ใช้ client/pool เดียวต่อ warm process ทั้ง development และ production ไม่แชร์ session หรือข้อมูลสิทธิ์ข้ามผู้ใช้
- การตรวจ session/พื้นที่ใน Server Components ใช้ React `cache` ภายในคำขอเดียว หน้าและ layout ใช้ผลตรวจเดียวกัน การตรวจจาก API ยังคงอ่านสิทธิ์ล่าสุด
- ผู้ที่เข้าสู่ระบบแล้วไม่ต้องนับผู้ใช้ทั้งหมดก่อนเปิดทุกหน้า การหาพื้นที่ที่ไม่ถูกลบใช้ relation filter แทนการโหลดรายการพื้นที่ที่ลบทั้งหมดมาเป็นอาร์เรย์
- หน้าภาพรวมรวมยอดใน PostgreSQL ไม่ดึงทุกสินค้า/ตำแหน่ง/Lot/ประวัติชั้นสต็อกมาวนใน Node.js ส่งผลเตือนเพียง 8 รายการและการเคลื่อนไหว 7 รายการ จำนวนรวมยังคำนวณจากข้อมูลทั้งหมด ไม่มี cache ยอดสต็อกข้ามคำขอ
- ดัชนีใหม่สำหรับยอดตามพื้นที่ Serial ตามสถานะ และประวัติล่าสุด แยกเป็น migration ละหนึ่ง `CREATE INDEX CONCURRENTLY` เพื่อรองรับ Prisma และไม่หยุดการเขียนตาราง
- ปิดการ prefetch ทุกเมนูใน shell เพื่อลดการโหลดหน้าพร้อมกันโดยไม่ได้เปิดใช้งาน
- ล็อกอินแสดงสถานะตั้งแต่ตรวจบัญชีจนเปิดหน้าใหม่ ใช้การเปิดเอกสารใหม่หลังเปลี่ยนตัวตน ป้องกันข้อมูล route เก่าค้างและไม่ส่ง `replace` กับ `refresh` ซ้อนกัน
- มี root/secure loading skeleton และแถบกำลังเปิดหน้าสำหรับการนำทางที่ผ่านตัวป้องกันงานค้าง
- เมนูและ page guard ใช้กติกาเดียวกัน ไม่มีพื้นที่จะเห็นเฉพาะเมนูที่ไม่ต้องใช้คลัง ผู้เรียนเห็นงานตามสถานะและประเภทโจทย์ รอบตรวจนับไม่เห็นลิงก์ยอดอ้างอิง เมนูมือถือและช่องค้นหาตรวจสิทธิ์ด้วย
- Scrollbar บาง 6px/`thin` สำหรับทุก scroll container พร้อมสี hover และรองรับ reduced motion ไอคอนเว็บเป็น SVG คลังสินค้า ใช้ไฟล์เล็กและไม่มีการเรียกสร้างภาพขณะเปิดเว็บ

## ผลตรวจ

- Build/type check ผ่าน
- `tests/page-access.mjs`: บทบาท พื้นที่ สถานะรอบฝึก และงานตามโจทย์
- `tests/workspace-auth.mjs`, `tests/stock-workflow.mjs`, `tests/training-research.mjs`, `tests/workspace-deletion.mjs`: ผ่านบน PostgreSQL QA แยก
- `tests/dashboard-summary.mjs`: เทียบยอดจริง ยอดพร้อมจ่าย Serial FEFO วันหมดอายุ การจอง ผลเตือน และพื้นที่ว่างกับข้อมูลอ้างอิง ผ่านเมื่อเพิ่มประวัติชั้นสินค้าว่าง 5,000 รายการ ข้อมูลอ้างอิงขนาด 2,494,506 bytes เทียบกับผลสรุป 2,456 bytes ผลนี้เป็นขนาดข้อมูลที่โหลด ไม่ใช่การวัด RAM ทั้งระบบหรือความเร็ว Vercel จริง
- ตรวจหน้าจอเข้าสู่ระบบจนเห็น loading และหน้าภาพรวม เมนูเจ้าหน้าที่ไม่มีบัญชีผู้ใช้/แบบฝึก ตรวจ favicon และ scrollbar จาก DOM มือถือ 390px ไม่มีหน้าล้นแนวนอน

ยังไม่ได้วัดเวลา/หน่วยความจำบน deployment Vercel จริง ต้อง deploy แล้วใช้ Observability ตรวจ duration และ memory ของ function ใน region ใหม่ ข้อมูลทดสอบไม่ถูกใส่ใน Supabase งานจริง

อ้างอิง: [Vercel region configuration](https://vercel.com/docs/project-configuration/vercel-json), [Next.js prefetching](https://nextjs.org/docs/app/guides/prefetching)
