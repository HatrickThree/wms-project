# คู่มือทดสอบรับงาน WMS ในเครื่อง

ขอบเขตที่ยืนยัน 28 ตุลาคม 2026: ตรวจรับในเครื่องนี้ก่อน ยังไม่เผยแพร่คลาวด์ ไม่เพิ่มบัญชีตัวอย่างหรือยอดฝึกลงพื้นที่ธุรกิจจริง

## เริ่มใช้งาน

1. เปิด `http://127.0.0.1:3000` และเข้าสู่ระบบด้วยบัญชีของผู้ใช้ ผู้ดูแลสร้างบัญชีเจ้าหน้าที่ ผู้สอน และผู้เรียนตามต้องการ ไม่มีรหัสผ่านเริ่มต้นร่วมกัน
2. เลือกพื้นที่ธุรกิจหรือพื้นที่ฝึกในเมนู **พื้นที่ธุรกิจ / การฝึก** ตรวจชื่อพื้นที่บนหัวหน้าจอก่อนบันทึกทุกครั้ง
3. ใช้พื้นที่ฝึกแยกสำหรับทดลอง ข้อมูลสินค้า คลัง ตำแหน่ง Serial และเอกสารอยู่ภายในพื้นที่ของตนเอง

## งานคลัง

| งาน | วิธีตรวจรับ | ผลที่ควรได้ |
| --- | --- | --- |
| ข้อมูลหลัก | เพิ่ม SKU แบบจำนวนและแบบ Serial ตั้งหน่วยแพ็ค/กล่องพร้อมอัตราแปลง | ยอดเก็บเป็นจำนวนเต็มในหน่วยหลัก อัตราขณะทำรายการอยู่กับประวัติ |
| รับเข้า | รับหลายหน่วยพร้อม Lot/วันหมดอายุ ทดลอง Serial ซ้ำ | FEFO ต้องระบุ expiry; ข้อผิดพลาดไม่เพิ่มยอดบางส่วน |
| จอง/หยิบ/จ่าย | สร้างคำสั่งซื้อ จอง ลองตำแหน่งผิด แล้วหยิบถูกและยืนยันจ่าย | จองและหยิบยังไม่ลดถือครอง จ่ายลดเมื่อยืนยันแล้ว ห้ามจ่ายหมดอายุ |
| จัดเก็บ/ย้าย | ย้ายจากจุดรับเข้าไปจัดเก็บ ทดลองย้ายยอดที่จองแล้ว | ยอดรวมคงเดิม Lot/วันรับเข้าเดิมคงอยู่ ย้ายยอดจองไม่ได้ |
| ตรวจนับ | เลือก SNAPSHOT หรือ LOCK ก่อนเริ่ม ตรวจทุกตำแหน่ง ส่งผู้อนุมัติ | ไม่แสดงยอดอ้างอิงขณะนับ ปรับยอดหลังอนุมัติพร้อมเหตุผลเท่านั้น |
| ABC | วิเคราะห์แล้วสังเกตกลุ่มปัจจุบัน จากนั้นผู้มีสิทธิ์ยืนยัน | การวิเคราะห์อย่างเดียวไม่เปลี่ยนกลุ่ม รอบวันแก้แยก A/B/C และอิงวันนับที่อนุมัติ |
| คำสั่งซ้ำ | ถ้าการเชื่อมต่อขาด กดตรวจผลรายการเดิม | ไม่รับเข้า ย้าย จอง หรือจ่ายซ้ำจากการลองเดิม |

การข้าม FIFO/FEFO ต้องผู้ดูแลธุรกิจหรือผู้สอนฝึกพร้อมเหตุผล แต่ข้ามข้อห้ามสินค้าหมดอายุไม่ได้ การปล่อยจากกักกัน คืนหลังหยิบ และรับคืนจากลูกค้ายังไม่เปิด workflow โดยอัตโนมัติ

## ผังคลังและเส้นทาง

1. เปิด **ผังคลัง / เส้นทางหยิบ** เลือกคลัง สร้างผังเสนอจากตำแหน่ง แล้วปรับพิกัด สเกล และทางเดินให้ตรงผังจำลอง
2. เพิ่มจุดทางเดินเมื่อจำเป็นต้องเดินอ้อม เชื่อมเฉพาะทางที่เดินได้จริง ระบุทางเดียวหรือสองทิศทางได้
3. บันทึกผัง จากนั้นเลือกคำสั่งซื้อที่จองแล้วและมีรายการยังไม่หยิบ กดคำนวณและเก็บแผน
4. ตรวจจุดหยิบ รายการสินค้า และระยะทาง แผนเก็บผังรุ่นนั้นไว้ แม้แก้ผังปัจจุบันแล้ว

ใช้ Dijkstra ระหว่างจุดและเลือกจุดถัดไปใกล้ที่สุดตามทางเดิน ไม่รับรองว่าเหมาะที่สุดทั้งรายการ และไม่ใช้เส้นตรงแทนเมื่อทางเดินไปไม่ถึง ระยะเป็นค่าจากผัง ไม่ใช่ระยะเดินจริง การคำนวณแผนไม่ทำรายการสต็อก

## เตรียมห้องเรียนและรอบฝึก

1. ผู้ดูแลสร้างบัญชีผู้สอนและผู้เรียน ผู้สอนสร้างพื้นที่ฝึกและเพิ่มสมาชิกผู้เรียน
2. เตรียมสินค้า หน่วย คลัง ตำแหน่ง สต็อกตั้งต้น และผังในพื้นที่ฝึกแม่แบบ ห้ามใช้พื้นที่ธุรกิจเป็นแหล่งคัดลอก
3. ปิดงานจอง หยิบ และตรวจนับค้างในแม่แบบก่อนเปิดโจทย์ ยอดรวม ชั้นสต็อก และ Serial ต้องตรงกัน
4. ใน **ห้องเรียน / รอบฝึก** สร้างร่าง เลือกงานรับ/ย้าย/หยิบ/นับ คำสั่งงาน รายชื่อ และรูปแบบแยกคนหรือร่วมทีม กำหนด Seed และเลือกว่าจะใช้ Seed เดียวกันทุกกลุ่มหรือไม่
5. เพิ่มรายการเกณฑ์ ระบุหน่วย TPQI วิธีเก็บหลักฐาน และเกณฑ์จำเป็น ผู้สอนตรวจเทียบแหล่งมาตรฐานก่อนกดยืนยันการจับคู่
6. เปิดโจทย์ ระบบสร้างคลังใหม่ต่อคน/ทีม พร้อมสำเนาข้อมูลตั้งต้น โดยไม่เปลี่ยนแม่แบบหรือธุรกิจ รายชื่อและโจทย์ของรอบที่เปิดแล้วไม่แก้ทับ
7. ผู้เรียนเลือกพื้นที่รอบของตน กดเริ่มรอบ แล้วเปิดงานที่ได้รับมอบหมาย ผู้เรียนจัดการข้อมูลหลัก อนุมัติข้อยกเว้น หรือทำงานนอกประเภทที่เปิดให้ไม่ได้
8. ส่งงานเมื่อครบเงื่อนไข ระบบหยุดเวลาและปิดการเปลี่ยนสต็อกของผู้เรียนในรอบนั้น ผู้สอนตรวจหลักฐานและสรุปสมรรถนะรายคนจนสมาชิกครบ

ข้อจำกัดของแม่แบบระยะแรก: ไม่เกิน 100 SKU, 1,000 ชั้นสต็อก, 2,000 Serial และ 20 กลุ่มต่อโจทย์ วันรับเข้าและวันหมดอายุคงเดิม ไม่มีการเลื่อนวันเพื่อทำให้สินค้ากลับมาใช้ได้

### สถานการณ์จำลอง

- **ปกติ:** ใช้สต็อกตั้งต้นตามแม่แบบ
- **ขาด/เกิน:** ใช้กับงานนับ สร้างชั้นสินค้าจำลองแยกจากยอดบัญชี ผู้เรียนสแกน/กรอกตำแหน่งเพื่อดูสิ่งที่พบ แล้วกรอกผลนับ ยอดธุรกิจไม่เปลี่ยน
- **ออเดอร์ด่วน:** ใช้กับงานหยิบ สร้างใบเบิก `SIM-URGENT-001` ในรอบนั้น ผู้เรียนจอง ตรวจหยิบ และจ่ายตามกฎปกติ

Seed, รุ่นกฎ และ hash แม่แบบอยู่กับรอบ จึงตรวจที่มาของสถานการณ์และทำซ้ำได้เมื่อแม่แบบกับกฎเหมือนเดิม ยังไม่มีโมเดล AI ทำงาน

## ผลสมรรถนะและตัวชี้วัด

ผลเป็น **ผ่านเกณฑ์ / ยังไม่ผ่าน / หลักฐานไม่ครบ** จากผู้สอน พร้อมหลักฐานรายเกณฑ์และรายบุคคล ผ่านได้เมื่อเกณฑ์จำเป็นทุกข้อมีหลักฐานที่ผู้สอนตรวจว่าผ่านแล้ว ไม่มีคะแนนรวมถ่วงน้ำหนักและไม่ออกใบรับรอง TPQI

ตัวชี้วัดแยกจากผลสมรรถนะ:

- เวลาเริ่มถึงส่งงานจากเซิร์ฟเวอร์ รวมเวลาพัก
- คำสั่งตรวจหยิบที่ผ่าน ÷ คำสั่งตรวจหยิบที่ระบบตรวจแล้ว ไม่รวมข้อมูลผิดรูปแบบก่อนเข้าส่วนคำสั่งคลัง และไม่นับงานที่ผู้สอนทำแทน
- ระยะตามแผนที่เก็บไว้ รวมแผนล่าสุดต่อคำสั่งซื้อ/คลัง เป็นค่าคำนวณจากผัง

รอบทีมใช้ตัวชี้วัดรวมของทีม ผู้เรียนเห็นผลสมรรถนะของตนเอง ผู้สอนตรวจเหตุการณ์ที่มีชื่อผู้ทำรายการเพื่อประกอบหลักฐานรายบุคคล

## แบบทดสอบและเครื่องมือวิจัย

1. ผู้สอนสร้างร่างประเภทก่อนเรียน หลังเรียน ผู้เชี่ยวชาญ หรือความพึงพอใจ กำหนดรหัสชุด รุ่น คำชี้แจง และคำถาม
2. รองรับตัวเลือก มาตราส่วนจำนวนเต็มที่กำหนดช่วง และข้อความ แบบก่อน–หลังระบุเฉลยตัวเลือกก่อนอนุมัติ
3. ผู้สอนตรวจแล้วอนุมัติรุ่น จึงเปิดให้ตอบ เฉลยไม่ส่งให้ผู้เรียนและแก้คำถามรุ่นที่เปิดแล้วไม่ได้ ต้องสร้างร่างรุ่นใหม่
4. ผู้เชี่ยวชาญใช้บัญชีบทบาทผู้สอนที่ได้รับเชิญในพื้นที่ฝึก คำตอบที่ส่งแล้วไม่ถูกแก้ทับจากการลองซ้ำ
5. ผู้สอนดูคำตอบและส่งออก CSV ได้ คะแนนจำนวนข้อที่ถูกเป็นผลเครื่องมือความรู้ ไม่แปลงเป็นผลสมรรถนะอัตโนมัติ

รหัสผู้ตอบคงที่ในพื้นที่เดียวกัน เพื่อจับคู่ผลก่อน–หลังกับผลฝึกได้ การส่งออกไม่ใส่ชื่อบัญชีผู้ตอบเป็นคอลัมน์ แต่ข้อความคำตอบ/ชื่อรอบอาจระบุตัวบุคคลได้ จึงไม่อ้างว่าเป็นข้อมูลนิรนาม การอนุมัติในระบบไม่แทนการตรวจความตรง/ความเที่ยงของเครื่องมือวิจัย

## ป้าย กล้อง และเสียง

- สร้างป้าย QR/Code128 จากสินค้า ตำแหน่ง หรือ Serial ภายในพื้นที่ ดาวน์โหลด PNG และจัดพิมพ์ A4 ได้
- เปิดกล้องเมื่อผู้ใช้เลือกเท่านั้น หรืออ่านรหัสจากภาพ การอ่านรหัสช่วยกรอกช่อง ยังต้องทบทวนและบันทึกขั้นตอนงาน
- เสียงอ่านเริ่มปิด เลือกเสียงภาษาไทยบนอุปกรณ์ เปิดเอง แล้วอ่านขั้นตอนหรือผลตรวจใหม่ได้ มีปุ่มหยุดและหยุดเมื่อซ่อนแท็บ/เปลี่ยนหน้า ไม่มีคำสั่งเสียงเปลี่ยนยอด

ยังต้องทดสอบโดยผู้ใช้กับกล้องมือถือ เครื่องพิมพ์ และเสียงจริงของอุปกรณ์เป้าหมาย การใช้งานกล้องผ่านเครือข่ายต้องเตรียม HTTPS ตามสภาพแวดล้อมที่เลือกในระยะติดตั้ง
