# stockspace WMS — Supabase / PostgreSQL

ระบบบริหารคลังและการฝึกปฏิบัติ ใช้ Next.js App Router, TypeScript, Prisma 6, PostgreSQL บน Supabase และ shadcn/ui

## เริ่มต้นใช้งาน

1. สร้าง Supabase Project แล้วใส่ `DATABASE_URL` (Transaction pooler) และ `DIRECT_URL` (Session pooler/Direct) ใน `.env` โดยดูแม่แบบ `.env.example`
2. ใช้ Node.js 24 และรัน `npm ci` จากนั้น `npm run db:deploy` เพื่อติดตั้งโครงสร้างในฐานข้อมูลใหม่
3. รัน `npm run dev` และเปิด `http://127.0.0.1:3000` สร้างผู้ดูแลใน `/setup` เฉพาะกรณีเริ่มฐานข้อมูลใหม่ที่ไม่ย้ายบัญชีเดิม
4. หากย้ายข้อมูล SQLite เดิม ให้ทำตาม [คู่มือ Supabase และ Vercel](docs/SUPABASE-DEPLOYMENT.md) ก่อนเปิดใช้งาน ไม่ใช้ seed/reset ทับข้อมูลจริง

ไม่ต้องตั้ง `APP_ORIGIN` และไม่มีการตรวจปฏิเสธ Origin แล้ว ระบบยังตรวจบัญชี บทบาท และพื้นที่ที่เลือกตามเดิม

รายละเอียดค่าการเชื่อมต่อ การย้ายข้อมูลเดิม การทดสอบ และขั้นตอน Vercel อยู่ใน [คู่มือติดตั้ง](docs/SUPABASE-DEPLOYMENT.md)

## หน้าจอ WMS

หน้าจอใช้ **shadcn/ui + Radix UI + Tailwind CSS 3** รองรับมือถือและเครื่องสแกนแบบคีย์บอร์ด ประกอบด้วยภาพรวมคลังจากข้อมูลจริง ค้นหาสต็อก รับเข้า จ่ายออก และประวัติ Serial

- รับเข้า: สแกนสะสมก่อนบันทึก พร้อมตรวจ Serial ซ้ำและเตือนงานค้าง
- จ่ายออก: ตรวจ Serial และชั้นวาง แล้วทบทวนในกล่องยืนยันก่อนตัดจ่ายจริง
- ค้นหา: เก็บตัวกรองใน URL รองรับวันที่ตาม Asia/Bangkok และแสดงขอบเขตสูงสุด 300 S/N ชัดเจน
- ตาราง Serial ใช้ TanStack Table เรียงและแบ่งหน้าเฉพาะข้อมูลที่โหลด
- ประวัติแสดงสถานะภาษาไทยและการเคลื่อนไหวตามเวลาไทย

อ่านรายละเอียดดีไซน์และขอบเขตระยะถัดไปใน [เอกสาร UX/UI](docs/WMS-UX-UI-SHADCN.md)

ตรวจสอบสำหรับ production ด้วย `npm run build` หากติดตั้งแพ็กเกจหรือเปลี่ยนการตั้งค่า Tailwind ขณะที่เว็บเปิดอยู่ ให้เริ่มเซิร์ฟเวอร์พัฒนาใหม่เพื่อโหลดการตั้งค่าให้ครบ

## บัญชี พื้นที่ และป้ายรหัส

- ผู้ดูแลเข้าถึงทุกพื้นที่ เจ้าหน้าที่เฉพาะพื้นที่ธุรกิจที่ได้รับสิทธิ์ ผู้สอน/ผู้เรียนเฉพาะพื้นที่ฝึกที่ได้รับมอบหมาย
- พื้นที่ใหม่เริ่มว่าง ไม่คัดลอกสต็อกธุรกิจให้อัตโนมัติ ข้อมูลสินค้าและ Serial ใช้รหัสเดิมซ้ำได้คนละพื้นที่
- การสลับพื้นที่ในอีกแท็บทำให้แท็บเดิมบันทึกไม่ได้จนรีเฟรช ป้องกันงานเข้าผิดพื้นที่
- ป้าย QR / Code128 สร้างภายในระบบจากข้อมูลพื้นที่ปัจจุบัน ดาวน์โหลด PNG หรือจัดพิมพ์ A4 ได้
- กล้องเริ่มเมื่อผู้ใช้กดเปิดเท่านั้น อ่านจากภาพได้ด้วย การอ่านรหัสช่วยกรอกช่อง ไม่บันทึกรับ/จ่ายอัตโนมัติ กล้องมือถือผ่านเครือข่ายต้องใช้ HTTPS
- เปลี่ยนรหัสผ่านหรือระงับบัญชีจะเพิกถอน session ที่มีอยู่ อายุ session สูงสุด 12 ชั่วโมง

ตรวจเวอร์ชันเว็บด้วย `npm run check` ซึ่งสร้างผลลัพธ์ใน `.next-check` แยกจากเว็บพัฒนา ชุดทดสอบใช้ PostgreSQL ทิ้งได้บนเครื่องเท่านั้น โดยมี `ALLOW_DISPOSABLE_DATABASE=1` และชื่อฐานข้อมูลมีคำ test/qa ตามข้อกำหนดในคู่มือติดตั้ง

ติดตามส่วนที่ยังไม่ครบใน [ข้อกำหนด Concept Paper](docs/CONCEPT-PAPER-REQUIREMENTS.md)

## งานคลังที่เพิ่มแล้ว

- ข้อมูลหลักสินค้า/คลัง/ตำแหน่ง หน่วยบรรจุราย SKU พร้อมอัตราแปลงเป็นหน่วยหลัก
- รับเข้าแบบจำนวนหรือ Serial พร้อม Lot/วันหมดอายุ และป้องกันคำสั่งซ้ำ
- คำสั่งซื้อ → จอง FIFO/FEFO → ตรวจหยิบ → ยืนยันจ่าย ยอดถือครองลดเมื่อยืนยันจ่ายเท่านั้น
- จัดเก็บ/ย้ายตำแหน่งโดยคงวันรับเข้าเดิม และห้ามย้ายยอดที่จอง/หยิบแล้ว
- ตรวจนับทั้ง SKU แบบไม่แสดงยอดอ้างอิงระหว่างนับ ส่งตรวจและอนุมัติผลต่างพร้อมเหตุผล ตรวจการเปลี่ยนยอด/จองก่อนปรับ
- ABC จากความถี่เอกสารจ่าย เก็บข้อเสนอแยกจากกลุ่มที่ยืนยัน และกำหนดจำนวนวันนับรายกลุ่มได้
- บันทึกผู้ทำรายการและเวลาจากระบบ พร้อมประวัติ StockLedger/Serial เดิม

เส้นทาง `/api/outbound` แบบตัดจ่ายตรงเดิมตอบ 410 พร้อมคำแนะนำให้ใช้ Orders; `/api/inbound` ใช้ payload แบบ receipts ใหม่ที่มี operationId และจำนวน แนะนำใช้หน้าจอหรือ `/api/receipts`

ชุดทดสอบเพิ่ม: `tests/stock-workflow.mjs` ต้องเป็นฐานว่างที่มี migration แล้วและยังไม่มีบัญชี ส่วน `tests/counts-abc-transfers.mjs` ใช้ต่อจาก stock-workflow บนฐาน QA เดิมเท่านั้น `tests/abc.mjs` ตรวจคำนวณล้วน ไม่ต่อฐานข้อมูล ห้ามใช้ seed/reset หรือคำสั่งทดสอบกับข้อมูลทำงาน

## ผังคลัง ห้องเรียน และเครื่องมือวิจัย

- `/maps`: ผังจำลองปรับพิกัด สเกล ทางเดินและจุดเริ่ม/จบได้ เก็บรุ่นและแผนเส้นทางตามใบจอง ระยะเป็นค่าคำนวณจากผัง
- `/training`: ร่างโจทย์และเกณฑ์อ้างอิง TPQI ระดับ 3 ผู้สอนตรวจ mapping ก่อนเปิด สร้างคลังแยกต่อคนหรือทีมจากแม่แบบฝึกเท่านั้น สถานการณ์ขาด/เกิน/ด่วนสุ่มด้วย Seed ที่ทำซ้ำได้
- ผู้เรียนทำงานได้เฉพาะรอบที่เริ่มแล้วและประเภทงานที่เปิดให้ งานตรวจนับไม่เปิดยอดอ้างอิง เวลา/ความถูกต้องของคำสั่งตรวจหยิบ/ระยะตามแผนแยกจากผลสมรรถนะ ผู้สอนตรวจรายบุคคลแม้เป็นรอบทีม
- `/research`: เครื่องมือร่างก่อน–หลัง ผู้เชี่ยวชาญ และความพึงพอใจ อนุมัติรุ่นก่อนเก็บคำตอบ ไม่ส่งเฉลยให้ผู้เรียน ไม่แก้คำถามหรือคำตอบที่ใช้แล้วทับ มี CSV ตามสิทธิ์พร้อมรหัสจับคู่ผู้ตอบ
- เสียงอ่านเปิดเอง ใช้เสียงไทยบนเครื่อง อ่านขั้นตอนและผลตรวจได้ ไม่มีคำสั่งเสียงเปลี่ยนสต็อก

คู่มือหน้าจอและการรับงาน: [WMS-LOCAL-ACCEPTANCE.md](docs/WMS-LOCAL-ACCEPTANCE.md) ผู้ใช้ยืนยันให้ทดสอบในเครื่องก่อน ยังไม่เผยแพร่ภายนอกหรือเปลี่ยนฐานข้อมูลสำหรับใช้งานหลายคน

การทดสอบ workflow ใหม่เรียงบนฐาน QA ใหม่ที่ migrate แล้ว: `stock-workflow.mjs` → `counts-abc-transfers.mjs` → `warehouse-map-api.mjs` → `training-research.mjs` ส่วน `workspace-auth.mjs` ใช้ฐาน QA แยกที่ยังไม่มีบัญชีและมีข้อมูลคลังสาธิตจาก seed เท่านั้น การทดสอบกฎล้วน: `abc.mjs`, `warehouse-map.mjs`, `training-rules.mjs`


การลบพื้นที่ธุรกิจ/การฝึก: เฉพาะผู้ดูแลระบบ ต้องยืนยันชื่อพื้นที่และรหัสผ่านปัจจุบัน เป็นการนำออกจากการใช้งานโดยเก็บข้อมูลไว้ และกู้คืนได้จากตัวกรองพื้นที่ที่ลบในหน้า `/workspaces` ดูขั้นตอนตรวจรับใน `docs/WMS-LOCAL-ACCEPTANCE.md`
